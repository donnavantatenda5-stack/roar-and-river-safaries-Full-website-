# Roar and River Safaris - full Next.js project

Complete, ready-to-run website: homepage, per-tour detail pages, /book booking form
(Supabase + Resend email), TypeScript, Tailwind CSS v4, framer-motion animations.

## Project structure

This is one Next.js app, with the frontend and server-side implementation grouped separately:

| Folder | What lives there |
| --- | --- |
| `frontend/` | Frontend page implementations, UI components, shared site chrome and styles |
| `app/` | Thin Next.js route/layout entry points and the assistant API bridge |
| `public/` | Images, logo and video served by Next.js from its required root public folder |
| `lib/` | Shared content and helpers used by both sides (tours, activities, site details, validation, types) |
| `backend/` | Backend: API logic, server actions, Supabase client, mailer and database schema |

Next.js requires route entry points and global layouts to live in `app/`, so those files
delegate page rendering to `frontend/pages` and shared UI to `frontend/`. The public asset
directory also stays at the project root as required by Next.js. See `frontend/README.md`
and `backend/README.md` for details.

## Pages

| Route | What it does |
| --- | --- |
| `/` | Homepage: hero, destinations, tours grid, why-us, how to book |
| `/tours` | Index of all signature tours and activities |
| `/tours/[slug]` | Full detail page per tour (itinerary, what's included, price, book CTA) |
| `/book` | Booking form |
| `/book?tour=[slug]` | Booking form with that tour's details shown above it |

## Run it (Windows PowerShell)
    npm install
    copy .env.example .env.local
    npm run dev
Open http://localhost:3000

The homepage works immediately with the built-in tour list. To enable bookings:
1. Create a Supabase project, open SQL Editor, paste backend/supabase/schema.sql, Run.
2. Fill in .env.local (Supabase URL + key, Resend key, notify email, optional WhatsApp number).
3. Restart `npm run dev`, then test at http://localhost:3000/book

## River Guide assistant (Gemini)

The floating chat widget in the bottom-right answers from the tour data in this repo,
pulls a live Victoria Falls forecast from Open-Meteo (no key needed), recommends
activities that suit the weather, links into `/book`, and routes price negotiation to
WhatsApp, phone or email.

On supported browsers, tap the microphone beside Send to record a question. Allow
microphone access when prompted; review the transcript, then tap the microphone again
to send it. The assistant reads its reply aloud. Voice features depend on browser
support and microphone permissions; typing remains available.

Answers are generated by Google Gemini through `app/api/assistant/route.ts`. The key
stays on the server:

1. Create a key at https://aistudio.google.com/apikey
2. Add it to `.env.local`:
       GEMINI_API_KEY=your-key
3. Restart `npm run dev`.

Optional overrides: `GEMINI_MODEL` (default `gemini-3.6-flash`, with automatic fallback to `gemini-3.5-flash`), `GEMINI_THINKING_BUDGET` (default `2048` reasoning tokens) and `GEMINI_API_URL`
(default `https://generativelanguage.googleapis.com/v1beta/models`).

Without a key the route returns 503 and the widget silently falls back to its built-in
rule-based replies, so tours, weather, booking and contact answers still work.

## Editing tour content

Long-form tour content lives in `lib/tourDetails.ts`, keyed by tour slug: summary,
start time, duration, minimum group size, meeting point, the paragraphs, what's
included, and the Important callout. This is deliberate, so the site renders before
the database is connected. Only `price_usd`, `name`, `image_url` and `description`
come from Supabase. A `description` in the database overrides the summary line in
`lib/tourDetails.ts`.

Prices in the database seed are in `backend/supabase/schema.sql`. To change a price on a live
site, update the row directly:

    update public.tours set price_usd = 229 where slug = 'chobe-day-trip-botswana';
